# Light Lambda — local incremental delivery

Supported local layer/ZIP/RIE tooling and copy-paste commands are in [PACKAGING.md](PACKAGING.md). Default Validator activation stays closed; Router rewriting remains unavailable.

The runnable baseline and selected-fixture WP13 commands are in
[REGISTERED-DELIVERY.md](REGISTERED-DELIVERY.md). They build the real bootstrap and exercise
Init/service locally. WP13 is incremental; full-inventory conformance is open.

WP12 is in progress. See [the completion matrix](WP12-COMPLETION.md) for the
current implementation, registration and local qualification gates. Router now
has a registered forwarding-only profile; nonempty rewrite rules fail Init.
Validator remains unavailable. Local qualification is separate from deployed proof.

`bootstrap` is the app entry point. The pinned `lambda_runtime` SDK owns polling
and invocation response/error posting; the framework reports pre-run Init
failures once with a bounded 2-second `/init/error` attempt and exit 1.

## Commands

- No arguments or `run`: prepare the required deployment directory, initialize
  the qualified configured policies, security and AWS Invoke, then run the SDK.
- `validate-config [--config-dir <dir>]`: local preparation, artifact checks and
  plan compilation, without AWS clients/providers, key bootstrap, token fetches,
  Runtime API calls, registration or a bound application transport. Prints
  `{valid, errors, warnings, configDigest, handlers, routes}` and exits 0 or 1.
- `--print-embedded-config`: print embedded templates only, using the existing
  config-loader CLI helper for each file.
- `--dump-embedded-configs <dir>`: export the same embedded templates through
  that helper. Effective deployment secrets are never printed or exported.

Unknown/malformed arguments exit 1 locally and cannot silently start the runtime
or call its Init-error reporter.

## Configuration and deployment identity

`config/` is the authoritative build-time embedded source, generated by
`config_embed_build::generate()`. The retained template under
`tests/serverless-conformance/phase1-templates/handler.yml` is an exact reference
copy, not a second runtime source. The earlier template is preserved in WP10
approval history. Java obsolete handler audit flags were removed; only
`audit.auditOnError` and `audit.auditStackTrace` are supported. Java cleanup:
https://github.com/networknt/light-4j/issues/2811

`LIGHT_LAMBDA_CONFIG_DIR` defaults to `/opt`, and that directory must exist and
be readable. Embedded defaults never replace a missing deployment directory.
`values.yml` resolves the Java-style `${file.key:default}` placeholders. Stage
is required; reserves require `0 < postReserveMs < responseReserveMs`.

Runtime startup requires the standard region/function/version/memory variables
and the trusted deployment `LIGHT_LAMBDA_GATEWAY_ARN` (full function ARN).
It supplies account/region/self-target validation before any invocation; the
incoming event cannot supply this identity. This environment setting must be
provided by later deployment tooling; no deployment was performed in WP10.
Offline validation can use it for exact identity checks. Otherwise it uses a
synthetic identity (and configured accountId if present), with a warning that
local validity does not establish remote targets, credentials, keys or readiness.

JWT verification and expiry checking are enabled by default, token logging and
SWT verification are disabled. JWKS refresh uses the existing shared WP6 gate
and the embedded `security.jwksRefreshMinIntervalSecs` default of 30. Java SWT
header defaults differ from shared Rust defaults; these deferred settings retain
their Java key names with the Phase-1 accepted shared defaults. Certificate maps
default empty; nonempty certificate settings remain unavailable. Business
Invoke always uses `LogType::None`; the Java `logType` key remains recognized.
No insecure sample values are imported into production defaults.

The Java request/response/admin chains are retained. Embedded handler aliases
cover their names and may be replaced through the existing Java handler values.
Qualified factories include the existing security factors, header/CORS,
correlation/traceability, limiter/token, Audit/Metrics, Specification, Sanitizer
and fixed-profile request/response Transformers. Most policies remain opt-in
through disabled templates; enabling an unavailable policy fails Init.
Validator matching/worker prototypes do not establish request-validation support.
`status.yml` admits only absent/default true flags and exactly matching stock
catalogue entries, with ignored-default diagnostics. Custom catalogue overrides,
unknown settings and false/malformed flags reject at Init, including values-only
settings. The fixed status renderer is unchanged.
`handler.reportHandlerDuration` is a closed CFG-04 exception: absent/false is
warned once and ignored before the strict compiler; true/malformed fails Init.
The compiler's missing-terminal and unknown-key validation is unchanged.

## Reserved local endpoints

The owner-approved Phase-1 amendment omits Java local routes whose terminals
are unavailable. An app-owned guard reserves `/health`, `/adm/health`,
`/adm/server/info`, `/adm/logger`, and `/adm/cache/{name}` for every HTTP method.
It runs after the existing ALB decoder and before configured policy/route
selection. A broad/default proxy route cannot bypass it, and there is no
production bypass switch. Cache names use one nonempty path segment, exactly
as the core template matcher does. No additional percent decoding occurs.
`/healthz`, trailing/extra segments and other unrelated paths route normally.

Qualified opt-in Health, Info and GetLogger terminals can bind their GET routes.
Protected Info/GetLogger routes require actual verified OAuth/JWT authentication;
Basic/API-key protected-admin proof remains owner-deferred. Info is redacted and
GetLogger reports the installed immutable filter. Unavailable, incorrectly bound
or unsupported reserved routes retain local `404 / ERR10007`, zero dispatch and
one finalization. Logger mutation/cache operations remain unavailable.

## Local L1 qualification

`tests/l1/` spawns `env!("CARGO_BIN_EXE_bootstrap")` with a cleared environment,
synthetic credentials/identity, disabled IMDS and test-owned Runtime API, Invoke
and generated-key JWKS endpoints. Warm cases deliberately reuse a process.
Child waits and server cleanup are bounded; owned children are terminated after
successful response assertions, and this harness termination is recorded
separately from natural exit 1 on Init/transport failures.

Endpoint evidence strips signing/Authorization headers and verified claims.
Offline tests count accepted TCP connections at Runtime API, JWKS and
Invoke/credential-provider sentinels, rather than assuming an unroutable address
proves no connection attempt. L1-04/04b observe actual Invoke EOF within the
remaining budget. L1-08 verifies the approved SDK HTTP-500 log-and-resume rule;
it is not delivery acknowledgment or an exactly-once business guarantee.

WP12/WP13 remain incomplete; Router rewriting, Validator activation/precision qualification and the remaining compatibility gates stay open. Router forwarding has its accepted factory/built-app/comparison checkpoint. Current coverage is recorded in the completion matrix rather than inferred from package availability. Supported baseline layer tooling, reproducible bootstrap-only ZIP and proxy-only local RIE are documented in PACKAGING.md; broader L2 and AWS/L3 qualification remain open.
