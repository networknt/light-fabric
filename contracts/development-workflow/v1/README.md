# Personal development workflow contracts v1

Issue: https://github.com/networknt/light-fabric/issues/392

The authoritative wire schemas are the public Serde types in
`crates/development-workflow-contract/src/{lib,review,stage}.rs`. Objects reject
unknown fields, required fields have no permissive defaults, struct fields use
camelCase, and enums use kebab-case. `FeatureRun.schemaVersion` is exactly `1`.
Optional fields may be omitted or null. These are contracts for Workflow
state and validated worker results; they are not Portal event-importer files.

Run the Phase 0 gate from the repository root:

```sh
bash scripts/run-development-workflow-phase0-gates.sh
```

`feature-run.json` and `stage-claim.json` are matching, import-free stage-start
fixtures. The executable fixtures in `tests/phase0.rs` cover review replay,
duplicate/closure ambiguity, disputes, coverage, sign-off, budgets, handoffs,
publication revisions, comment sequencing and VM release. The worker-facing
`review-result.schema.json` and `remediation.schema.json` have matching wire
fixtures and are checked against the Rust parser by the gate.

## Contract ownership

| Contract | Authority and invariant |
| --- | --- |
| `RequirementArtifact`, `PhaseDefinition` | Accepted inputs carry scope, criteria, repository ownership, dependencies and declared checks; unresolved requirement decisions block freeze. |
| `FeatureRun`, `StageClaim`, `StageClaimReceipt` | Workflow allocates transitions. Identity includes feature, transition, predecessor and stage/phase. The request digest binds all inputs. Historical replay precedes current-version checks; changed inputs conflict. |
| `StageResult`, `StageAcceptancePolicy` | Acceptance binds the active claim, input versions, exported candidate, declared checks, persisted reviewer results and required publications. Policy comes from Workflow. |
| `CandidateSnapshot`, `DeltaReceipt` | Manager-produced snapshots include repository bases/trees, checkpoint and manifest digests, and durable package references. Delta evidence binds before/after snapshots and impact routing. |
| `FindingLedger`, `ReviewBinding`, `ReviewResult` | Workflow preallocates a review before dispatch. Canonical finding IDs use feature/review/local identity with domain-separated, length-framed SHA-256, independent of wording. Replays return the same mapping; changed results conflict. |
| `Remediation`, `HumanDisposition` | Implementers can submit fixes or disputes. Only the owning reviewer closes/reopens, or an authenticated human waives/defers with reasons and tracking. Duplicate references do not close findings. |
| `ReviewCoverage` | Full Codex review precedes full Claude review; intervening fixes resume the same reviewer session. Full verdict digests remain immutable. Every transition needs complete delta/check evidence and explicit unaffected-scope carry, or both reviewers for broad changes after both have started. |
| `BudgetLedger`, `NonProgress` | Logical dispatched turns, including output/validation repairs, consume budget once. Three remediation rounds per stable scope is the default. Reopens and replacement stage instances retain this ledger and deadline. Repeated still-open IDs route to human resolution. |
| `DesignSignoff` | Optional by run policy; approval binds the exact feature and accepted design digest. Rejected, missing or superseded approval cannot satisfy a required gate. |
| `VmReservation`, `VmReleaseReceipt` | A terminal feature plus confirmed fencing/reconciliation of every outstanding execution/effect is required for release. The receipt binds owner and generation. |
| `DocumentRevision`, `PublicationReceipt`, `CommentIntent` | Every document revision has a new immutable publication task. Delivery receipts bind candidate/commit/ref/PR. Status versions increase; round/publication comment identities and bodies are immutable on retry. |

## Phase 1 integration obligations

This crate has no database, network, model, filesystem or clock side effects.
Time is an explicit input. It validates reference structure, not the existence or
bytes of an artifact, a real mTLS peer, a human authorization, or a remote effect.
Never accept a worker-supplied ledger, acceptance policy, impact classification,
check list, preallocation, clock, budget scope, or receipt as authority.

Phase 1 must authenticate actors, verify artifact contents/digests and external
receipts, load authoritative state/policy, and call these rules under transactional
locks. Persist stage claim, invocation/process/initial task and ownership together;
record/replay review allocation and result mappings atomically. Dispatch and fixed
effects must require the claim. Budget scopes/round identities belong to the
feature and cannot be regenerated by a reopened phase or worker. Charge before
dispatch; capacity waiting is not a dispatched logical turn. Non-progress
observations must be applied in committed review order with a pinned threshold.

`validate_handoff` is a structural preflight; `validate_acceptance` adds reviewer,
finding, policy and publication checks. Final delivery also requires
`ReviewCoverage::validate_publication`, the current sign-off policy, verified
snapshots and authorized Git/GitHub effects. Required validation sets supplied to
coverage are authoritative; widening/changing them requires explicit replan.

The Phase 0 reference model preserves a reviewer session through a coverage chain.
If history/binding is lost, Phase 1 must record recovery and obtain a fresh full
review before starting a replacement chain; silently substituting a session is
rejected. Artifact persistence, atomic start races, runner transfer, model loops,
GitHub effects, and actual VM fencing remain Phase 1 work.
